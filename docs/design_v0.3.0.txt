Moment 插件 设计文档 v0.3.0
=====================================
日期：2026-09-30        当前版本：v0.2.0  →  目标版本：v0.3.0
涉及需求：贝佳妍评论我的动态 / 删除我发错的评论 / 新增点赞功能


一、关于「贝佳妍也该评论我的朋友圈」
-------------------------------------
结论：代码层面她已经可以了，这条不需要改代码，是我上一条说法错了。

原因：NPC 挑人是纯随机（npc_engine.pick），只看名单、不看帖子作者。
      所以不管动态是我发的还是他发的，8 个人都有机会现身。

需要确认的边界问题：
      贝佳妍的人设里写着「与沈星回并不熟识」，但随机挑人的结果是，
      她也可能出现在沈星回的动态下面，热情留言，这会跟人设打架。

      可选方案（做不做由你定，默认先不做）：
      在 NPC 名单里支持第三段「出现范围」，格式：
          贝佳妍|女，邱诺亚的女朋友……|只在他不出现
          陶桃|……|优先在我的动态下出现
      只对写了第三段的 NPC 生效，没写的照旧随机。改动很小（约 30 行）。


二、删除自己的评论
-------------------------------------
现状：数据库有 delete_comment 方法，但没有对外接口，页面上也没有按钮。

改动：
1. 新增接口 POST /api/comments/delete
   接收 comment_id；只允许删除 author='user' 的主评论（即我发的），
   他发的、NPC 发的评论一律拒绝，避免误删对话。
2. 删除时同步清理挂在它下面的回复（外键 ON DELETE CASCADE 已开启）。
3. 页面：我发的评论右侧加一个小的「删除」，点一下二次确认后消失，
   同时评论数 -1。
4. 兜底：接口会检查评论是否属于自己，不存在或不属于自己的返回明确错误。

顺带说明：现在库里我自己发的评论有两条 —
    #1 在「出门早了，书店还没开门…」下面：「看看猫」
    #4 在「螺蛳粉好辣！」下面：「超级辣呀」
你要删的是哪条，告诉我我可以直接处理；不着急的话等删除功能上线你自己点。


三、点赞功能
-------------------------------------
设计定位：点赞是「谁赞了」这件事，跟帖子里现有的「表情」（贴纸）不是同一件事，
          所以单独建表，不去动现有的 reactions 逻辑。

1. 数据库：新增 likes 表
   post_id / author（'user' / 'ai' / 'npc'）/ author_name（NPC 名字）/ created_at
   同一人对同一条帖子只能赞一次（唯一索引保证）。
   旧数据不用迁，新表自动建。

2. 接口：
   POST /api/likes/toggle   点赞 / 取消赞
   /api/posts 返回时给每条帖子带上 likes 汇总（谁赞了、赞数、我赞没赞）

3. 页面：
   - 每条动态底部加一个「❤ 赞」按钮，点一下点亮，再点取消。
   - 点亮后按钮下方显示一行字：「沈星回、陶桃 觉得很赞」。
   - 数字保留，方便一眼看热度。

4. 他也会点赞（重点，这个比按钮本身有意思）：
   - 我发动态后，他有配置好的概率来点个赞（默认 0.6，可关）。
   - NPC 也会点赞：复用现有名单和概率配置，随机 0~2 人，各自带延迟，
     像真的陆续刷到。点赞用的是同一个人设池，不需要额外配置。
   - 点赞不推送聊天通知，只在页面显示，免得变成噪声。

5. 配置项新增（都会进 _conf_schema.json，有默认值）：
   like_enabled            点赞功能总开关（默认开）
   ai_like_probability     他给我动态点赞的概率（默认 0.6）
   npc_like_probability    NPC 点赞的概率（默认 0.5）
   npc_like_count_max      一次最多几个人赞（默认 2）

顺带修一个 bug：
   现在 /api/posts 不返回表情数据，所以页面上的表情只有当次点击后能看到，
   刷新就没了（数据其实一直在库里）。这次一并修掉，跟点赞一起返回。

五、风险与边界
-------------------------------------
- 点赞表新增，不影响已有数据；出问题可整表删掉重来。
- 删除评论不可撤销，所以只给自己的评论开这个口子。
- 不改任何现有接口的入参，旧页面缓存不会崩。
