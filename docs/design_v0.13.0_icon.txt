Moment v0.13.0 设计文档 —— 网页图标与「添加到主屏幕」
==========================================================

一、需求
----------------------------------------------------------
用户提供一张插画（1179x1179 正方形，深蓝夜空 + 月牙 + 仓鼠捞星星），
希望将它作为朋友圈网页的图标，并能在手机上「添加到主屏幕」使用。

二、目标
----------------------------------------------------------
1. 浏览器标签页 / 书签显示该图标（favicon）。
2. 手机添加到桌面后，桌面图标为同一张插画。
3. iOS 下从桌面图标打开时以独立窗口（standalone）运行，体验接近 App。
4. 图标为空闲静态资源，不受访问密码拦截，登录页也能正常显示图标。

三、方案
----------------------------------------------------------
源图构图本身已铺满画布（自动检测非背景区域约占 3%~94%，四周几无留白），
因此不做裁剪，仅按各平台推荐尺寸等比缩放。

新增文件（均位于 pages/timeline/assets/，属插件静态资源，非运行数据）：
  assets/icon-180.png          180x180 ，供 apple-touch-icon
  assets/icon-192.png          192x192 ，供 Android / manifest
  assets/icon-512.png          512x512 ，供 PWA 启动画面
  assets/favicon-32.png         32x32  ，供浏览器标签页
  assets/favicon.ico             多尺寸  ，供 /favicon.ico 兜底
  assets/manifest.webmanifest    Web App Manifest

未生成 1024x1024：本次未配置启动画面，该尺寸只会多占约 1MB 仓库体积。
六个文件合计约 0.6MB，均为 RGBA 全彩，未做有损压缩。

Web App Manifest 要点：
  name/short_name  : Moment
  display          : standalone
  start_url        : /
  scope            : /
  background_color : #1d3f66（取自源图背景）
  theme_color      : #1d3f66
  icons            : 192 / 512，purpose 为 any 与 maskable

页面 head 增补（pages/timeline/index.html）：
  <link rel="icon" type="image/png" sizes="32x32" href="/static/favicon-32.png">
  <link rel="icon" type="image/png" sizes="192x192" href="/static/icon-192.png">
  <link rel="apple-touch-icon" sizes="180x180" href="/static/icon-180.png">
  <link rel="manifest" href="/static/manifest.webmanifest">
  <meta name="theme-color" content="#1d3f66">
  <meta name="apple-mobile-web-app-capable" content="yes">
  <meta name="apple-mobile-web-app-status-bar-style" content="default">
  <meta name="apple-mobile-web-app-title" content="Moment">
  <meta name="mobile-web-app-capable" content="yes">

服务端路由（core/standalone_server.py）：
  /static/{filename}      由 add_static 提供，指向 pages/timeline/assets
  /favicon.ico            读 assets/favicon.ico
  /favicon.png            同上，部分浏览器会请求这个变体
  /apple-touch-icon.png           读 assets/icon-180.png
  /apple-touch-icon-precomposed.png  同上，iOS 6 及更早的旧名字
  /manifest.webmanifest   读 assets/manifest.webmanifest

上述根路径别名是必要的：无论页面 head 里写了什么路径，浏览器与 iOS 都会
额外去根路径请求 /favicon.ico 和 /apple-touch-icon.png，不兜住就会报 404。
别名一律指向 assets 内的固定文件，不接受外部传入文件名。

四、与既有实现的关系
----------------------------------------------------------
本次开发前，pages/timeline/ 根目录下已被放入三份手写的图标文件
（apple-touch-icon.png、favicon.png、favicon.ico），并注册了四个对应的
根路径路由，但没有修改 index.html 去引用它们，因此图标实际未生效；
也没有 manifest，无法以独立窗口打开。

本次将其统一收进 assets/，删除根目录残留，路由改为共用的别名实现，
并保留 apple-touch-icon-precomposed.png 这一旧名字兼容路径。

五、路径穿越防护
----------------------------------------------------------
静态目录由 aiohttp 的 add_static 管理，其内部已做规范化与目录逃逸拦截。
自己实现的 /favicon.ico 与 /manifest.webmanifest 两个端点只读固定文件名，
不接受外部传入的文件名参数，因此不存在穿越风险。

六、密码与登录页
----------------------------------------------------------
中间件目前仅拦截 path == "/" 与 path.startswith("/api")。
/static/*、/favicon.ico、/manifest.webmanifest 均不在拦截范围内，
无需登录即可取到图标；登录页自身也会带上 favicon。
从桌面图标打开时会走 "/"，若配置了密码仍会先看到登录页，属预期行为。

七、兼容性说明
----------------------------------------------------------
iOS Safari：支持 apple-touch-icon 与 apple-mobile-web-app-capable，
            http 局域网地址同样可以「添加到主屏幕」并全屏运行。
Android Chrome：http 地址下「添加到主屏幕」可正常使用 manifest 中的图标
            与名称；部分版本的 standalone 完整生效需 HTTPS，不生效时
            退化为普通快捷方式，图标仍然正确。

八、版本变更
----------------------------------------------------------
新功能，minor：v0.12.0 -> v0.13.0

九、未纳入本次改动
----------------------------------------------------------
不引入 Service Worker，因此不提供离线缓存；离线场景仍由页面自身逻辑处理。
